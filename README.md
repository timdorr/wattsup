# ⚡ WattsUp

> **Real-time Solar Inverter Monitoring System**

WattsUp is a high-performance Go application designed to monitor Sol-Ark 15 solar inverters via Modbus RTU communication. It continuously collects power generation and consumption metrics, storing them in a TimescaleDB database for analysis and visualization.

[![Go Version](https://img.shields.io/badge/Go-1.25+-00ADD8?style=flat&logo=go)](https://golang.org/)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-TimescaleDB-316192?style=flat&logo=postgresql)](https://www.timescale.com/)
[![License](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

## 🌟 Features

- **Multi-Device Monitoring**: Simultaneously monitor multiple Sol-Ark inverters.
- **Real-time Data Collection**: High-frequency sampling of critical power metrics.
- **Robust Communication**: Modbus RTU over USB with automatic retry and error handling.
- **Time-Series Database**: Optimized TimescaleDB storage with automatic aggregation and data retention policies.
- **Production Ready**: Systemd service integration, graceful shutdown, and structured logging.
- **Tested**: Includes a suite of unit and integration tests.

## 🏗️ Architecture

```
┌─────────────────┐    ┌──────────────┐    ┌─────────────────┐
│   Sol-Ark       │    │   WattsUp    │    │   TimescaleDB   │
│   Inverters     │◄──►│   Monitor    │───►│   Database      │
│   (1-4 units)   │    │              │    │                 │
└─────────────────┘    └──────────────┘    └─────────────────┘
         │                       │                     │
    Modbus RTU              Go Application        Time-series
    USB Serial             Real-time Collection    Data Storage
```

### Core Components

- **`main`**: Entry point that initializes the application and starts the monitors.
- **`cmd`**: Command-line interface using Cobra, handles configuration and signal trapping.
- **`pkg/monitor`**: Core monitoring logic, including the Modbus client and data reading loop.
- **`pkg/config`**: Manages application configuration from a JSON file.
- **`pkg/sql`**: Database interaction layer generated by `sqlc`.
- **`db/migrations`**: Database schema migrations managed by `dbmate`.

## 🚀 Quick Start

### Prerequisites

- **Go 1.25+** (enforced at compile time)
- **PostgreSQL** with TimescaleDB extension
- **Sol-Ark inverter(s)** connected via USB
- **Linux system** (tested on Ubuntu/Debian)
- **`dbmate`** for database migrations

### Installation

1.  **Clone the repository**

    ```bash
    git clone https://github.com/timdorr/wattsup.git
    cd wattsup
    ```

2.  **Build the application**

    ```bash
    go build -o wattsup
    ```

3.  **Set up the database**

    ```bash
    # Create the database
    createdb wattsup

    # Install TimescaleDB extension
    psql -d wattsup -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"

    # Run migrations
    dbmate up
    ```

4.  **Configure devices**

    Create a `wattsup.json` file. A sample is not provided, but it should look like this:

    ```json
    {
      "database": "postgresql://user:password@localhost:5432/wattsup",
      "devices": [{ "name": "Inverter 1", "file": "/dev/ttyACM0", "id": 1 }],
      "registers": [
        { "name": "Load Watts", "address": 178 },
        { "name": "Grid Watts", "address": 169 },
        { "name": "PV 1 Watts", "address": 186 },
        { "name": "PV 2 Watts", "address": 187 },
        { "name": "PV 3 Watts", "address": 188 },
        { "name": "Battery Watts", "address": 190 },
        { "name": "Battery SOC", "address": 184 }
      ]
    }
    ```

5.  **Run the application**
    ```bash
    ./wattsup
    ```

## 🐳 Production Deployment

A `wattsup.service` file is provided for running WattsUp as a systemd service.

1.  **Copy the service file:**
    ```bash
    sudo cp wattsup.service /etc/systemd/system/
    ```
2.  **Reload systemd, enable, and start the service:**
    ```bash
    sudo systemctl daemon-reload
    sudo systemctl enable wattsup.service
    sudo systemctl start wattsup.service
    ```
3.  **Check the status:**
    ```bash
    sudo systemctl status wattsup.service
    ```

Logs can be viewed using `journalctl`:

```bash
journalctl -u wattsup.service -f
```
